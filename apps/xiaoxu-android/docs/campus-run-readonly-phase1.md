## 开源调研结论（2026-11-06）

1. [Inverx/com.zjwh.android_wh_physicalfitness](https://github.com/Inverx/com.zjwh.android_wh_physicalfitness)：根 `LICENSE` 为 MIT；README 列出了 score/history/policy 等只读研究模块，**同时**包含轨迹生成、结果上报、自动验证码和安全组件逆向。只参考一般数据字段，不复制上游源码，不依赖其认证/上报模块。
2. 当前没有证明该应用向第三方提供受支持的官方授权 API；必须先确认允许的本人只读访问或官方导出能力。GitHub 示例代码可运行不等于正式接口受支持。
3. 后续如复用上游 MIT 源码片段必须逐项审查功能、安全与上游版权，并更新 THIRD_PARTY_NOTICES；本阶段没有复制第三方实现。

## 数据契约与门禁

- **两种来源**：`TRUSTED_READONLY`（实际授权且完成身份匹配）和 `USER_IMPORT`（本人提供的文件，永远不能冒充实时官方同步）。
- **数据缺失**：`targetMeters/effectiveMeters/rawMeters=null` 表示未知；`0` 仅表示确有零记录的可核实结果。
- **有效里程** 单独保存；有效里程进度仅用可信学期有效里程，不以原始跑步距离或历史记录合计推算。
- **历史完整性**：`historyComplete` 只有数据源明确提供完整分页证据才为 true，否则最多是已读部分。
- **新鲜度**：数据捕获超过 36 小时、刷新失败或设备时钟异常时标记 `Stale`；失败不覆盖旧记录。
- **隐私**：不保存密码、学校 Cookie、Token、个人原始轨迹或设备身份；校序本人退出/源授权撤销时必须调用 `clear()`，未来持久化还需绑定校序 owner。
- **边界**：不进行自动运动、虚构跑步、行为伪装、验证码绕过或结果提交。

## 2026-11-06 官方页面截图：指标与状态对应（不含个人资料）

经用户提供的官方 App 两处界面可确认以下**字段语义**，但并不代表校序已获自动读取权限：

| 官方标签 | Kotlin 数据字段 | 规则 |
| --- | --- | --- |
| 学期目标 | `targetMeters` | 仅取明确展示的目标；不能从历史条目估算 |
| 计入成绩里程 | `effectiveMeters` | 唯一用于学期目标完成度、剩余计分里程的距离 |
| 学期累计总里程 | `rawMeters` | 属于学期记录页；不等于计入成绩里程 |
| 进度首页的累计跑量 | `dashboardAccumulatedMeters` | 累计区间未明，不能当作学期里程或与之相加 |
| 本周跑量 | `weeklyMeters` | 独立周范围；本周 0 必须与缺失 null 区分 |
| 学期累计跑步次数 / 计入成绩次数 | `totalRunCount / effectiveRunCount` | 页面“—次”表示未知 null，而不是 0 |
| 单次运动类型 | `CampusRunRecord.kind` | 计分跑 / 自由跑 / AI 运动 / 室内锻炼等，需由官方文本确认 |
| 达标/不达标 | `CampusRunRecord.status` | 是记录层状态，不自行推断单次计入多少里程 |
| 存在异常 | `CampusRunRecord.hasAnomaly` | 独立布尔/未知，与达标状态分离 |
| 已跑公里 / 跑步时长 | `rawMeters / durationSeconds`（单次） | 距离、时长独立，不能只按距离推导达标 |

两处官方页面同期展示的“累计跑量”与“学期累计总里程”不同，具体统计口径尚未证明，**不以减法推导未达标里程，也不把两个数字相加**。对于尚无法确认证据的字段维持 null。

**隐私门禁**：原始截图显示了个人 ID 和运动习惯信息；公开 Issue、PR、fixture 或文档不得复制这些值、具体跑步记录或图片；当前单测全部使用合成数据。

## 阶段 1.1：已有原生可用入口（非自动接入）

在 `教务 → 校园服务` 内添加 `CampusRunPanel`，**不改变五个一级导航**。
- 本人可手动录入官方 App 已显示的学期目标、计入成绩里程、学期累计、首页累计与本周里程。任意未见字段保留为 null，输入最长两位小数，数值以整数米保存。
- `LocalCampusRunStore` 使用 Android Keystore AES-GCM 和 `allowBackup=false` 下的本机 Preferences；没有任何外部网络请求和学校密码。
- 读取、校验、保存、重启恢复及主动清除均为可执行的真实功能；当前 `USER_IMPORT` 永远不升级为 `TRUSTED_READONLY`。
- 界面展示**明确的本机时间戳与人工录入标签**。历史记录为空时说明未导入，不填充模拟历史。
- 来源窗口不同的累计里程分别展示；只按 `effectiveMeters` / `targetMeters` 计算学期达标百分比。
- **暂不提供官方登录/自动刷新**：前面 HAR 的服务器响应为 `r/s/v` 载荷，尚未获得已证实、允许的第三方本人读取方式，故不基于逆向请求构造假的“同步”按钮。
- 安全限制：手动记录仅绑定当前设备的本地存储，**未来如允许多个校序 Owner 共用同一设备，必须在正式发布前做账户隔离或注销清除测试**。本阶段没有宣称跨设备同步、完整历史记录、同步授权闭环。
- 在 PR CI 中通过 `Gradle :app:testDebugUnitTest` 和全仓回归后才能合并；必须在 Android 16 真机按录入—保存—重启—删除流程验收，才标记 App 功能可交付。
