# 校序 · 运动世界校园只读查询管线（阶段 2：适配边界）

跟踪 [#302](https://github.com/07xh/dorm-os/issues/302)；基于已合并的 #303 / #307 工作，不重复建设校园跑账号管理、导航或存储。

## 本阶段已提交的真实代码

- `CampusRunReadOnlySource`：学期汇总、带游标的历史记录、授权账号指纹，全部为只读抽象。
- `CampusRunReadOnlyQuery`：按同一上游身份顺序读取并检查每个响应；原子生成 `CampusRunSnapshot`。
- 校序现有 `CampusRunSnapshotGate`：网络失败只标记旧快照过期；授权失效立刻清空；不同上游账号必须清除原缓存。
- 明确最多读取 20 页 / 1000 条（可配置、上限 100 页 / 1000 条）。超过上限时只保存部分历史并标记 `historyComplete=false`，绝不按记录求和伪造学期计入成绩里程。
- 合成数据 JVM 测试：账号不一致、未授权、有效与原始里程不同、完整/部分分页、重复游标、错误标记、过期、账号切换、授权撤销与网络故障。

**注意：这是可编译的查询管线，不是已经接通运动世界校园的线上适配器。** 没有增加 HTTP 请求、上游认证、页面抓取、编码响应解密，也没有上线自动同步。现有手动输入仍明确标记 `USER_IMPORT`，不会因此自动升级为 `TRUSTED_READONLY`。

## 真正接入前必须解决的最小阻塞

1. 确认运动世界校园允许的本人只读授权或可导出渠道；取得返回字段结构和真实使用范围。不能把学校端教师导出接口当作学生个人可用授权。
2. 由未来实现的来源适配器，在正常授权的会话中读取本人身份，生成经域分离的 SHA-256 指纹。上游学期和历史响应必须与同一身份核验；不能仅依靠调用方填写“账号一致”。
3. 明确学期目标、官方计入成绩里程、原始学期里程、首页累计与本周范围；未知保留 `null`。
4. 明确历史分页终止证据、单次跑状态/异常、记录稳定 ID；认证状态变更与单一校序 Owner 内切换学校账号应独立隔离。
5. 通过真实本人 App 逐项对照 + Android 16 断网/失效/退出/重启验收后，才把查询管线绑定到现有「我的 → 数据连接」和「教务 → 校园服务」。

## 开发与验收原则

- 不新增一级导航、不重复创造登录页面，也不改变校序其他数据源。
- 不存运动世界密码、Cookie、Token、原始轨迹；不上传个人运动数据到公共仓库。
- 源适配器还未实现时，不显示可点击但无效果的“实时查询/自动同步”入口。
- PR CI 与 Kotlin JVM 单测通过只证明查询层可用，不证明上游授权、正式部署或真机自动同步。
