# TapFlow KernelSU 模块全面审计 — V1.22.1

审计对象：`modules/dormos-nfc-ksu/`、Android App 的 `RootModuleClient` / `KsuActionRunner`、打包工作流。
目标设备：OnePlus Ace 6 / Android 16 / KernelSU。当前结论区分 CI 证据与真机证据。

## 本轮已修复

1. **统一互斥锁**：此前文件夹新增、重命名、移动、删除与脚本/NFC 执行共用锁存在缺口。文件夹写操作现在与脚本执行共用 `script-run.lock`；支持 `flock`，不支持时回退到 fail-closed `mkdir`。
2. **NFC 总开关竞态**：此前 dispatcher 在锁外检查 NFC 开关，检查后到执行前可能被关闭。本轮把启用/禁用写入同一把锁，并在 `--run-bound` 获锁后再次检查开关。
3. **临时文件**：脚本保存、重命名、绑定/解绑、场景更新、文件夹重命名/移动/创建改为 `mktemp` 唯一临时文件，再原子替换，避免固定 PID/固定 .tmp 文件被残留文件或并发操作干扰。
4. **权限失败处理**：关键存储目录权限设置失败时不再静默继续，改为明确报错。
5. **版本与文档**：模块元数据更新到 `1.22.1 / versionCode 23`；README 说明独立安装、外部数据保留、Root 脚本风险和真机验收边界。
6. **回归测试**：新增 NFC 执行期间禁止关闭总开关、禁止文件夹写入、fallback 锁互斥及陈旧锁拒绝等用例。

## CI 已覆盖

- 模块 ID、版本元数据、文件结构与禁止常驻脚本检查。
- 所有模块 Shell 脚本 `sh -n`。
- 默认关闭、启用/禁用、错误/未绑定/禁用场景拒绝。
- SH 保存、读取、重命名、删除、语法错误拒绝、16 KiB 限制。
- 并发运行、运行期间删除/重绑拒绝。
- 文件夹层级、重复名称、循环引用、移动和删除规则。
- `flock` 路径与强制 `mkdir` fallback 路径。
- 模块 ZIP 根目录结构与 APK 单独构建。

## 仍未完成 / 不能用 CI 代替的验收

1. **Ace 6 真机**：KernelSU 授权、模块更新/卸载/重装、实际 `flock` 能力、NFC 前台/后台/锁屏/息屏启动行为。
2. **耗电**：模块无 daemon/service/polling/wake-lock 是代码层事实；实际 NFC 待机功耗仍须 A/B 测量，不能宣称零耗电。
3. **超时后的子进程**：20 秒 `timeout` 对脚本主体有限时，但用户脚本若主动后台化子进程，仍需真机验证进程组清理和锁 FD 生命周期；不把任意 Root SH 当沙箱。
4. **完整备份**：当前 App ZIP 只导出 SH 文件，不含 NFC 标签绑定、场景状态、文件夹结构和总开关。应作为下一项独立功能实现，并在导入时设计冲突策略与完整性校验。
5. **错误呈现**：App 的 `listFolders()` / `scriptFolders()` 目前把 Root 失败折叠为空列表；后续应让 UI 区分“确实为空”和“读取失败/忙碌”。
6. **保存一致性**：脚本正文与名称是两个文件，写入由锁保护，但读取端没有对所有只读查询加锁；后续可考虑快照式元数据格式，避免刷新恰逢写入时出现短暂不一致。

## 安全说明

模块只提供固定命令入口和 UUID/Base64 参数白名单，不会把导入脚本限制在沙箱中。SH 脚本以 Root 执行，必须由用户自行审阅；NFC UUID 可复制，不是防克隆凭证。个人数据存放于 `/data/adb/dormos_nfc_bridge/`，模块卸载不主动删除，避免误删。
