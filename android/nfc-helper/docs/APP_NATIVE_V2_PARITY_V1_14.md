# DORM NFC V1.14 · 原型 V2 交互对齐

## 唯一设计基准

- 原型文件：`dorm_os_nfc_interactive_v2_3.html`
- SHA-256：`0fd8368a1a41a175282d98ad5e47146dba241fb961bd3e3edc6063f15d91419b`
- 页面结构：仅「首页 / 场景 / 工具」三个底部主导航。
- 交互基准：原型的顶部动作按钮、场景筛选、场景详情、编辑底部弹窗、执行确认、日志、主题切换和工具列表。

## 原生页面对应

- 首页：动态问候、深蓝 NFC Hero、设备状态、真实已绑定场景。主按钮启动真实前台 NFC 只读扫描，扫描结果以底部弹窗呈现。
- 首页右上角：打开「外观与交互」主题面板。
- 场景页：显示真实 KSU 场景名称、关联 SH、单场景启停；筛选为「全部 / 已启用 / 已停用」。原型中的侧键筛选不移植。
- 场景详情：显示 NFC 标签 ID 与脚本；支持启停、编辑名称/脚本、确认后实际执行脚本、解除绑定。
- 新建场景：填写场景名称、选择本机 SH，随后进入真实 NFC 写卡；写卡回读验证通过后才建立 KSU 绑定与场景元数据。
- 工具页：脚本文件使用原型式紧凑列表；运行、绑定、编辑、只读预览、改名、移动、删除放入单项操作菜单。文件夹管理默认收起。
- 工具页管理：真实运行记录、脚本导入、主题和设备权限；普通 NDEF 读取/写入保留为独立工具。
- 顶部动作按钮：首页=主题、场景=新增、工具=运行记录。底部不增加第四个设置页。

## 必须保留的真实行为

- NFC 扫描只读；不写入、不执行 Shell。
- NFC 场景标签只保存随机 UUID，不保存账号、密码或命令。
- 新绑定必须经过真实标签写入和回读验证。
- 场景名称与单场景启停状态保存在 KernelSU 模块受保护目录；停用场景由 dispatcher 拒绝执行。
- Root 执行前显式确认；结果与日志以模块返回值为准，不允许展示模拟成功。
- 不提供侧键、三段式开关或侧键 Hook；用户已明确排除。
- 不创建演示场景或虚构执行记录；所有列表从本机模块状态生成。

## 验收门禁

1. `testDebugUnitTest` 与 `assembleDebug` 必须来自同一提交 SHA。
2. KernelSU shell tests 必须覆盖场景名称持久化、单场景停用拒绝执行、重新启用、解绑清理。
3. 实机检查首页/场景/工具三页、全部弹窗、主题、脚本编辑与导入、KSU 状态。
4. NFC 标签未到时仅能验收 UI、空状态、模块状态和脚本管理；真实读写、锁屏触发与待机耗电不得提前宣称通过。
5. APK 未通过最新 CI 前，不得作为可安装版本交付。
