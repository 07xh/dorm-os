# DORM NFC V1.12 · 交互、失败反馈与真实标签验收

## 本轮变更

- 复用现有 Kotlin Compose / Android SDK NFC 和 KSU 安全桥；未新增导航页面、后台服务或第三方 NFC 框架。
- `NfcVisualComponents.kt` 统一只读扫描与通用写卡的标题、状态卡片、进度提示与明确操作按钮。
- ReaderMode 仅当前台页面可见时启用。读卡的 session generation 防止切走或重置后旧回调污染新的扫描结果。
- 写卡分别展示“准备—等待贴卡—写入与回读—已验证/未验证”，从根本上区分已经发出写入与确认成功。
- 如 NFC 关闭，提供直接打开系统 NFC 设置入口；无 NFC 设备不展示无用的扫描按钮。
- 读取时显示实际 NDEF 消息已用容量、最大容量、可写状态和真实记录数（只渲染前 24 条）。
- 对 NdefFormatable（未格式化）与非 NDEF 标签分别提示；不擅自格式化，保护既有标签内容。
- 识别 DORM 标签时使用友好 MIME 名称，但读取器不会触发 Root。
- `NfcFailureFeedbackTest.kt` 覆盖读取断连、写入不确定、空间不足、未格式化标签和回读不一致提示；失败信息不展示底层异常中的敏感内容。

## 一加 Ace 6 / Android 16 真机验收矩阵

下面均需使用本人拥有的可读写普通 NFC 标签；**不能通过 CI 或浏览器模拟自动认定通过**。

| 场景 | 操作 | 正确结果 |
| --- | --- | --- |
| NFC 关闭 | 关闭 NFC，打开读卡和写卡 | 明确显示 NFC 未开启，能进入系统 NFC 设置，不尝试写入 |
| 普通文本标签 | 写入中文“学习模式”，再用只读页面读取 | 内容一致，正确显示容量、可写、消息大小 |
| 网址标签 | 写入 HTTPS URL 后读取 | URL 一致，扫描时不自动打开网页 |
| 已有普通记录 | 不勾覆盖直接贴卡，再勾选覆盖 | 首次拒绝；确认后写入、回读一致 |
| 已绑定的 DORM 标签 | 即使勾选普通内容覆盖仍贴卡 | 强制拒绝修改，不执行 SH；原有自动化绑定完整 |
| 只读标签 | 发起写入 | 提示不可写且不宣称成功 |
| 容量不足 | 尝试写入超过标签容量的长文本 | 提示所需与可用容量，拒绝写入 |
| 非 NDEF / 未格式化 | 用仅支持其他协议的标签或未格式化标签读取 | 展示标签不兼容或尚未格式化，不修改标签 |
| 中途移开标签 | 读取、写入/回读过程中移开 | 明确提示通信中断；如果写入已发出，只能报告“未经验证” |
| 离开页面 | 在等待读卡或等待写卡时按返回 | 停止新的 ReaderMode 操作，不保留常驻服务 |
| 多标签干扰 | 两张普通标签同时靠近 | 失败时明确提示移开其他标签再重试，不重复提交写卡 |
| 锁屏/息屏 | 使用已有 DORM UUID 标签，单独测试系统 NFC 分发 | 记录真实 OS 行为，勿从亮屏结果推断锁屏可用 |
| 权限撤销 | 在 KernelSU 管理器撤销 App 的 Root 后触发已绑定标签 | 不执行 Root，错误提示明确，不影响普通只读写卡 |
| 待机耗电 | 相同无线环境下，安装前后各记录一晚耗电 | 按实际测量记录，不宣称零耗电 |

## 结果记录

## 发布门禁

1. 必须检查 PR HEAD 的 Android `testDebugUnitTest` + `assembleDebug`、KSU ZIP、DORM OS CI。
2. 上面真机矩阵中核心读写、防覆盖、Root 安全与后台行为通过后，才考虑将草稿 PR 标记为可合并。
3. 暂不合并 `main`；发布签名 APK 必须单独检查签名配置和实际安装结果。
