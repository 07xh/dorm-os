# 校序 M6 · 改期重新提醒与统一作业列表去重

## 已实现（不需要任何真实学校账号）
- 个人提醒的已读标记从仅绑定作业/考试 ID，改为同时绑定**有证据的截止日期和时间精度**。同一作业从只知道日期升级为准确时刻，或考试改期、改开考/结束时间，会生成新的未读提醒。仍保持原任务和之前的已读数据库记录，不覆写。
- 日期和时刻不变时，跨设备同一用户的已读回执继续稳定。不同任务即使同名也分别提醒，不按标题合并。
- 云端作业 GET 列表在同一用户范围提供 `source_provider` 与 `source_external_id`，来自已关联的平台来源映射或旧版迁移来源。**不返回平台密码、Cookie、会话或签名 URL**。
- 本地学习通导入、个人五域快照和 D1 云端账本只在 `provider + externalId` 或真实旧任务 ID 匹配时隐藏重复的展示条目；同名但不同 ID 的作业不合并。本地任务原始内容与个人完成标记不被更改。
- 云端任务截止日统计与本地前台提醒候选也复用同一去重视图，避免同一作业重复计数/提醒。
- 更新 PWA shell 缓存版本以便手机和平板取得新版 JS；没有新增页面，也不扩大用户数据采集。

## 与旧已读回执的兼容
本批只改变将来提醒事件的 `event_key` 生成格式（`exam-v2`、`task-v2`），无 D1 结构变动，也不删除旧表。升级后，当前到期事项可能重新显示一次未读提醒，因为旧的 `exam:...`、`task:...` 没有包含原截止时间，无法安全地确定旧已读是否仍适用于现有日程。新格式之后，同一日期和时刻不会重复变成未读；改期会提醒。

未开启站内订阅的用户仍可查看个人到期收件箱，但不代表系统通知推送。个人考试快照仍属于用户上传，不能因此宣称学校账号已连通。

## 数据来源去重的证据门槛
只按同名、同日期、同课程不够可靠，必须使用平台来源及稳定记录 ID；与旧任务做迁移关联时还要保持用户归属。未提供该证据的记录，宁可显示两条并标注来源，也不能自动丢弃其中任何一条。即使 UI 隐藏重复条目，原始记录仍全部保存在本地存储或 D1，能安全撤回/核对。
