# 校序第二课堂 M24｜本人正常 CAS 登录与同步链路

## 本次改动
- 保留唯一入口「我的 → 数据连接 → 第二课堂」。只有服务端预检当前学校官方 CAS 简单表单通过，才显示本次输入账号与密码的表单。
- 后端只连接白名单 HTTPS 学校域名，只允许学校自有 CAS service 和本人只读业务接口。验证码、短信验证、加密脚本或未识别跳转立即停止；不绕过学校身份验证。
- 复用历史经合成测试的 CAS 传输逻辑并放入新文件 lib/academic-ncwu-secondclass-server.mjs，重用原真实 HAR 解析器、会话保险库和 D1 原子保存。
- 登录后必须独立验证本人学校账户身份、完整活动分页、素质分与志愿服务时长，才加密保存会话；网页打开官网或历史导入记录不构成已连接。
- 已连接支持手动同步、单来源断开；网页可见且会话有效时可按 30 分钟间隔尝试前台同步。关闭网页时不执行后台定时任务；自动推送未启用。
- 服务端可用 NCWU_SECONDCLASS_TRUSTED_SYNC_ENABLED=false 关闭此适配器；需现有 SCHOOL_SESSION_KEY 和已升级到 0012 的安全会话表。

## 验收与限制
- 合成请求测试覆盖 CAS 跳转、本人身份、只读业务请求、Cookie 域限制、验证码/交互要求及凭据不落库，均不使用真实凭据。
- 尚未经过本人账号实测端到端连接，也没有验证校方当前普通表单可被 Cloudflare Pages 完成认证。真实 CAS 若依赖 JS 密码变换或人工校验，会报错并停止。
- 不要求学校专门提供开放 API，但必须使用本人合法访问渠道并尊重学校的认证规则。不上传 HAR、Cookie、密码或实名记录到仓库或聊天。
