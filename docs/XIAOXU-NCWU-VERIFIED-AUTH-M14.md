# 校序 M14｜华水青果教务可信只读连接器（2026-11-03）

## 已核验的上游事实
- 华水公开教务入口为 https://jwmis.ncwu.edu.cn ，2026 年学校公告继续要求通过其本人账号进入教务系统。
- 2025 年学校公告说明：校主页教学服务可经**统一身份认证账号密码**进入；教务处直达入口可能使用独立的**教务系统账号密码**。具体以当前官方登录页为准。
- 学校统一身份认证页面可见认证方式和 CAS 回调到 **学校自身系统**；**没有确认校序的域名被注册为学校 CAS/OAuth/OIDC 第三方回调**。因此 **不能**把在学校官网登录等同于校序已取得学校会话。
- 参考：[华水选课公告](https://www.ncwu.edu.cn/info/1063/20217.htm)、[信息化办公室说明](https://www2.ncwu.edu.cn/xxb/info/1082/1659.htm)、[2026 秋教材公告](https://ncwu.edu.cn/info/1063/22666.htm)。

## 本阶段真实交付
1. `lib/academic-ncwu-verified-sync.mjs`：可信服务端连接器的原子写入边界。必须由后端受信任的 `adapter.verifySession()` 证明 `provider=ncwu`、`school=ncwu`、`scope=self`、当前校序 owner 绑定、官方数据源，然后分别读取**课表、成绩、考试**。
2. 所有记录复用 `lib/academic-contract.mjs` 严格校验，使用平台真实的稳定 ID、学期、周次、节次；允许明确证实的空列表，不把缺少/截断数据当成功。不猜作息时间。
3. 写入现有 `academic_connections`、`academic_verified_batches`、`academic_verified_records`（无新迁移、无密码存储）。三个业务分区读取均成功后才进行一次事务提交；失败保留上次成功快照并将既有连接状态标记为过期/错误。数据按校序 owner 隔离，保存受信任来源标记。
4. 「我的 → 数据连接」的**原华水教务卡片**新增折叠授权说明，无新导航页面。只能跳转学校官网；不在校序接收密码、验证码或 Cookie。
5. 测试涵盖：校序本人绑定、域名约束、字段/稳定 ID、重复记录、空结果证明、失败回滚、跨账号隔离、数据库无敏感会话、前端匿名页面不请求私有记录、手机宽度。

## 未完成 / 不可宣称上线的能力
- **真实华水会话验证适配器尚未实现。** 当前 `runVerifiedNcwuSync` 只接受由受信任服务端代码注入的适配器，仓库没有对外暴露触发学校登录的 POST API；模拟适配器仅在测试内使用。
- 用户正常打开学校网站无法让校序直接读取另一个域名的 Cookie，也不会创建学校绑定。不能靠前端传 `authorized:true` 或上传官方 HTML/凭据来冒充连接。
- 没有对华水本人账号做真实课表、成绩、考试字段对照；尚不能宣称自动同步已经接通。
- 待确认学校许可的第三方只读授权或可撤销的本人授权桥接后，才可编写正式 `verifySession/readSection` 实现，验证学期、课程、考试的实际数据与覆盖范围。正常网页登录界面应仍由学校官方托管。

## 上线与后续门禁
- 本 PR 的发布仅代表**服务端可信读取边界和界面说明可用**，不代表学校账号绑定开通。
- 下一步先验证学校现行登录机制、是否有正规可用的第三方只读授权/API 或本人端本地只读导出，再选择连接实现；不可为了点击「绑定」绕开验证码、登录限制或平台规则。
- 保留 M13 中一处登录、一处连接中心、一套 D1 数据模型的设计；不再新建第二套账号表/页面。
