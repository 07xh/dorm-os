# 学校会话状态真实校验：加密可读性门禁

## 修复的准确性问题

之前数据连接 API 在校序已有的学校会话记录上仅检查 `expires_at` 是否晚于当前时间，就把会话标记为 `active`。如果管理员轮换服务端 `SCHOOL_SESSION_KEY`、旧 D1 记录密文损坏或归属 AAD 不匹配，会话虽然已经无法解密，却仍被展示为有效，误导用户。

## 实现

- 连接中心读取状态时将服务端已有 `SCHOOL_SESSION_KEY` 传给 `schoolSessionStates`，不从浏览器获取学校密码、Cookie 或 Token。
- 状态判断先检查过期时间，再验证 AES-GCM 能否用对应校序 owner + provider 的附加认证数据成功解密。
- 解密不成功返回 `unreadable`，界面提示「本地学校会话无法验证，请重新连接」；不泄露解密错误、密文或学校身份。
- 密钥配置缺失或格式无效时直接返回空状态，**不允许宣称账户已授权**。
- 正常有效的加密会话仍显示 `active`，原有学校同步的身份验证流程保持不变。
- 加密可读只是必要条件，不是学校端实时可用性的证明。下一次同步仍需现有 `verifySession` 真实验证账号与课程来源。

## 合成测试

加入原有校序安全测试：正确密钥显示 active、随机轮换密钥显示 unreadable、密文损坏显示 unreadable、到期时间显示 expired、不同 owner 不可读取、撤销后状态消失。

不改变数据库结构、用户密码表、授权模式、学校官网认证方式、现有学业接口或源站请求。
