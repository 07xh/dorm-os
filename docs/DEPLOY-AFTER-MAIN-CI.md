# 校序发布门禁和登录会话时长交互修复

## 故障

主分支对同一提交并发执行两套完整桌面/手机 Playwright E2E：DORM OS CI 和 Deploy DORM OS to Cloudflare Pages 的 verify。主分支发布阻断时，日志中的青果课表解析测试及安全测试均成功，失败集中在动态页面的交互状态（特别是我的页中的会话时长选择框）。

进一步确认我的页整体重绘没有保存会话时长展开框的状态；当其他模块触发页面 render 时，已经展开的选项会被重新设为隐藏，造成真实用户点击失效和自动测试不稳定。

## 修正

- 我的页重绘前保存会话时长框的展开序号，重绘后恢复相同框的展开状态和 aria-expanded；同时恢复键盘焦点。关闭后仍保持关闭，不会自动展开。
- 新增真实浏览器回归，触发身份状态变化、强制重绘并检查展开、选值、Esc 关闭与焦点。
- Cloudflare 发布不再直接随 main push 并发运行相同 E2E，而是订阅同仓库 main push 成功的 DORM OS CI 的 workflow_run。
- 自动发布仅对 CI 已完成、结论 success 的精确 SHA 执行；两个 checkout、revision.json 和线上 SHA 比对使用 CI 的 head_sha。
- 手动发布只允许 main，并且仍运行完整 E2E 门禁；不能借手动流程绕过安全和交互检查。
- 新增部署工作流静态契约测试，防止发布条件被无意放宽。

## 不改变

不触碰青果/学习通/第二课堂身份认证、个人数据、Cloudflare D1 结构，也不将 HAR 认证材料上传仓库。正式学校账号仍需单独通过真人授权验证。

## 验收

- PR 桌面和手机浏览器测试全部通过。
- 合并后 main CI 先成功，随后 Cloudflare Pages 才自动触发。
- 发布流水线核验与成功 CI 一致的不可变提交号。
- 失败的 CI 不能发布；手动模式仍需完整测试。
