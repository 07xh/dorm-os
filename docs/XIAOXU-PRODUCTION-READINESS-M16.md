# 校序 M16｜真实生产 D1 与单人口令会话只读验收

## 目标：补齐「部署成功 != 数据库可用」的验证缺口
- 保留 **一个校序网页登录、一个「我的 → 数据连接」入口、一个学业 D1 账本**。
- 旧 /api/v1/health 只能确认少数表，不足以证明 0001–0010 全量迁移。M16 引入统一只读 schema 合约，测试现在检查 0001–0009 学业表和 0010 本地 owner 登录所需表及关键字段。
- 现有本人认证 `verifyAcademicAccess` 仍是所有私有 API 唯一入口；只有校序 owner 会话有效才能看到自检结果；无额外账号密码输入。
- 不开启学校登录/无人值守同步；学校账号连接仍独立验证。

## 代码和使用方式
- `lib/academic-schema-readiness.mjs`：固定的必需表、字段清单，对 D1 只读取 `sqlite_master` 和白名单 `PRAGMA table_info`。不会选择个人数据表中的记录。
- `GET /api/v1/health`：已登录情况下核查 D1 schema；owner_password 模式需要已建立 M12 0010 身份/会话表。仅返回预定义的缺失表/字段名称、校序登录和数据库状态；会话令牌、学生身份和其他账号数据从不返回。匿名仍 401 或按配置 503。
- `我的 → 数据连接 → 校序数据服务自检`：本人明确点击后才读取 `/api/v1/health`；无后台轮询，保持折叠展开状态。自检的“通过”只证明**校序 D1 和校序本人会话**，**不证明青果、学习通、第二课堂已经绑定**。
- `scripts/audit-academic-d1-production.mjs`：部署后只读核验**Pages 生产 D1 UUID 与 D1 列表精确匹配**，再由 Wrangler 远程执行固定 SQL：`sqlite_master`、必要列的 `table_info`、`foreign_key_check`、`quick_check`。不会写入任何数据库，也不会打印数据库名、UUID、成绩、学校账号、会话、原始 Wrangler 输出。
- `.github/workflows/deploy-cloudflare.yml`：增加只读校验步骤，并采用 `continue-on-error: true`，用于报告数据库权限不足/缺表而**不会伪称静态部署被回滚**。真实验收以 Actions 步骤与日志为准。

## 验收范围
- 使用内存 SQLite 顺序执行现有 0001–0010 迁移，验证全部表/字段齐全。
- 0001–0009 正常、缺 0010 时 owner_password 不可宣称就绪，旧 access 模式保持向后兼容。
- 缺 provenance 列、缺 owner 会话表均能检测。
- 合法、有效的本地 owner 会话访问 `/api/v1/health` 返回 ready；无会话拒绝，响应不含 token/hash/身份。
- 生产 D1 匹配错误、多候选及恶意数据库名失败关闭。
- Playwright 覆盖手机/桌面折叠展示、自检按需读取、缺失迁移不冒充已连接、滚动无横向溢出。

## 不可由本次检查推断的事项
- Cloudflare API token 是否授予 D1 远程只读权限：只能在生产 Actions 运行时确认。如果只读查询权限不足则报告不可用，不宣称迁移完成。
- 当前**用户自己的**校序会话是否有效：服务端测试用合成会话，真实使用需本人打开页面验证。
- 三个学校平台的授权/自动更新：没有真实、允许使用的完整授权会话，仍保持未连接。
- 不新增 D1 迁移、不主动补迁移、不重复开发凭证中心；若发现缺迁移，先核对现有 forward-only 流程和备份后单独处理。
