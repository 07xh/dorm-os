- 上游仓库：`https://github.com/znjhahaha/zhengfang-apk`

- 固定 commit：`bb3b80a6d64e4c2057c0544bb417696ceaa2a9ed`
- 固定 Git tree：`9284dad51679829d1182f05b57b33490b464e611`
- 完整树统计：1,369 个 tree entries、1,222 个文件对象，其中 846 个 Kotlin 文件。
- 上游许可证：GPL-3.0。原始 LICENSE、版权声明、资源和目录结构必须保留。

上游 v1.0.135 的 tag 指向上述 commit；该 commit 的 tree 与本文件记录的 tree SHA 一致。此前 PR #479 中使用的 v1.0.83 / `e3f2833a2fb1e184968724ee4c7f71ebc816a2dd` 不再作为迁移依据。

## 完整源码副本

固定版本的完整项目将原样放在：

`apps/xiaoxu-android/upstream/zhengfang-apk-v1.0.135/`

这是独立、只读的上游基线副本，必须包含整个仓库，而不只是 UI 组件：根 Gradle 工程、`app` 模块、Manifest、全部 Kotlin/Java 源码、资源、依赖配置、Gradle Wrapper、构建脚本、测试、插件、文档和 LICENSE。

导入时必须验证：
1. `git rev-parse HEAD` 等于固定 commit。
2. `git rev-parse HEAD^{tree}` 等于固定 tree SHA。
3. 上游文件对象数等于 1,222。
4. 复制后逐文件比较，内容与文件模式均与上游一致。
5. 不允许在导入时顺手改名、格式化、删文件或改写上游页面。

## 工作副本与不可变上游快照

为了既能直接迁移完整页面，又能保留可审计的原始版本，目录职责固定为：

- `apps/xiaoxu-android/upstream/zhengfang-apk-v1.0.135/`：不可变、只读的完整上游快照。
- `apps/xiaoxu-android/migrated/`：从同一 commit 复制的完整工作工程；首次导入时必须与上游 root tree SHA 完全一致。后续所有必要的校序适配只在此工作副本内进行。

两个目录初始都必须有 1,222 个文件，文件内容、文件模式和 Git tree SHA 与上游完全一致。CI 负责复制并校验两个目录；不要在只读快照中直接修改，也不要只复制 UI 文件到工作副本。

## 迁移顺序

1. **原版基线**：完整复制并独立编译 v1.0.135，保留原始页面、导航、状态管理、窗口/页面宿主、动画、玻璃材质、主题、资源和 Gradle 依赖。
2. **原版验收**：先确认上游原版可以构建、启动、切页、返回、打开设置和课表；记录原版截图及性能基线。
3. **业务适配**：在原版页面和状态架构内接入校序已有数据服务。只写必要的数据模型、Repository、ViewModel/接口适配，不另建 UI 架构。
4. **页面替换**：按完整页面/完整导航流程迁移，不能以复制单个组件、创建包装层或重新仿制样式充当复用。
5. **清理旧实现**：确认业务行为等价、无回归后，再删除旧自研页面和无引用代码；不保留长期双导航、双页面或双渲染体系。
6. **验收交付**：同一设备、同一数据、同一刷新率下，对比原版与校序版本；完成编译、JVM/仪器测试、APK 安装、真机交互和帧耗时测试后，才可标记完成。

## 明确禁止

- 禁止继续扩展自研 UI、第二套导航/页面/动画/材质架构。
- 禁止逐个组件手写、仿制或包装上游已有实现。
- 禁止从 v1.0.83、v1.0.135 或其他分支混合拼接页面。
- 禁止为接数据而大规模改写原版页面；优先改数据适配边界。
- 禁止把“源码已导入”说成“完整工程已集成”，也禁止把编译通过说成真机验收通过。
- 禁止在许可证审查完成前将组合后的 APK 作为正式版本分发。

## 当前阶段状态

本阶段只负责建立并验证完整、固定、可追溯的上游工程基线。它不代表校序业务已迁入，也不代表新 APK 或真机性能已经验收。
