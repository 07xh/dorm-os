# 校序 #351｜一加 Ace 6 Android 16 四页真机视觉与统一 APK 验收

> 状态：**采集工具已交付，真机截图与本人学校数据对照仍待实际执行**。模拟器、CI、网页预览或没有实际设备画面的设计稿不能替代本页签收。视觉标准优先使用用户提供的**北化课表原 App 截图**，不重新设计底部导航、课表星期条、课程配色或课程详情弹层位置。

## 1. 唯一构建与安装身份

- 整合主线：PR #351 `feat/xiaoxu-unified-native-mainline-20261106`；以 **PR 最新 HEAD** 及该 SHA 触发的构建为准。历史成功构建不得当作最新代码的成功证明。
- 同一构建运行 `Build Xiaoxu Android Alpha` 上传两种文件：
  - `xiaoxu-unified-native-qa-isolated`：`xiaoxu-unified-native-qa.apk`，包名 `io.github.x07xh.xiaoxu.unifiedqa`，用于视觉/导航及空状态验收。**独立存储，不会带入现有 App 的个人学校数据。**
  - `xiaoxu-android-alpha-debug`：`app-debug.apk`，包名 `io.github.x07xh.xiaoxu`，用于现有账号和真实数据回归；仅在已备份且确定签名与安装风险后人工安装。**不允许为做截图直接清除/卸载有真实数据的正式包。**
- 构建必须确认 `Build Xiaoxu Android Alpha`、`Xiaoxu Android JVM Regression`、`DORM OS CI` 全绿，并保存 `app-debug.apk.sha256` 或 `xiaoxu-unified-native-qa.apk.sha256`。构建成功只证明能产出 APK，不证明在 Ace 6 已安装。
- 正式合并/发布仍须独立门禁；此流程不向 `main` 合并、不接入虚构数据。

## 2. 本机采集（Windows + 已授权的 Android 16 Ace 6）

1. 用 GitHub Actions 对应 SHA 的 **Artifacts** 下载并解压隔离 QA APK；先比对同目录 `.sha256`。用 Android Platform Tools 的 `adb` 将其安装到本人设备：`adb install -r xiaoxu-unified-native-qa.apk`。不要用隔离 APK 覆盖正式 App。
2. 电脑安装 Node.js 与 Android Platform Tools；手机在**信任的电脑**上授权 USB 调试。`adb devices -l` 必须显示设备处于 `device` 状态。此工具不需要 Root。
3. 在仓库根目录执行：

   ```powershell
   node scripts/xiaoxu-ace6-visual-qa.mjs --apk "C:\\path\\xiaoxu-unified-native-qa.apk" --commit <对应Git提交SHA>
   ```

   多设备时增加 `--serial <设备序列号>`。如已有正式包且需要核对本人真实学校数据，**另开一次采集**并显式传 `--package io.github.x07xh.xiaoxu`；不得将两个包的结果合并冒充同一会话。
4. 按提示依次进入首页、课表、课表设置、任务中心、任务详情、消息中心、消息详情。每次先真实点击/滚动/返回，再采集 PNG 与 `dumpsys gfxinfo`。没有真实数据的详情直接输入 `skip`，不制造课程/通知。
5. 输出位于用户主目录的 `Xiaoxu-Visual-QA/<时间戳>/`。包含原始 PNG、帧统计与 `manifest.json`（设备型号、Android 版本、包名、提交、APK SHA256）；默认**不上传到 GitHub 或云端**。截图可能包含本人课程、姓名、群消息，分享前应自行遮盖。

## 3. 四页同屏对照矩阵

| 页 | 与北化原图对照 | 行为回归（不得因视觉调整而丢失） |
| --- | --- | --- |
| 课表 | 顶栏高度与字号；星期选择不改；课程六色不改；周/日只在课表设置；弹层位置、文字、圆角一致 | 上下周、周次选择、滚动、点课程进原生详情、文件导入、编辑和返回 |

### 视觉统一参数（核验时以原图/真机为最终标准）

- 字体由 `XiaoxuTypography` 统一供给，页面标题与列表字号在 4 页对照；不能以任意页面自身 `fontSize` 再造体系。
- 卡片与弹层优先复用 `XiaoxuRadius`、`XiaoxuSpacing`、`XiaoxuCard`、`XiaoxuSheet`；仅保留北化参考明确要求的局部差异。
- 导航/分段切换使用共享交互组件；对比选中态、连续点击、拖动回弹、返回、键盘弹出和页面恢复。性能数据必须来自实际设备 `gfxinfo`，不能从代码的动画时长推断流畅。
- 每页至少做 3 次切换/滚动，记录是否首帧空白、闪烁、重复顶栏、布局跳动或点击误触；至少检查一次后台返回。帧统计缺失时写“未测得”，不能填 0。
- 视觉/滚动结果须分别记录“通过 / 不通过 / 未验证”。**CI 成功不自动勾选任何真机项。**

## 4. 真实数据与发布底线

- 数据核对必须在原 App 包内，以用户本人正常授权的学习通/青果/第二课堂页面为准，逐项比对课程、作业、截止与提交状态、活动与积分；只验证 UI 展示不等于三平台数据接入成功。
- 未授权、刷新失败、快照、无课程/无活动必须准确显示，关闭 App 重新进入仍应能核对本机记录与登录态；不为视觉截图注入演示数据。
- 只有 PR 当前 HEAD 的 Android APK + JVM + 综合 CI 全绿、原始截图及帧报告完整、用户本人 Ace 6 对照签收后，才能清退对应页剩余旧入口并进行正式版合并/发布。

**当前不能虚报：** 自动化工具不具备直接操作用户一加 Ace 6 的能力；脚本交付与 CI 构建不能冒充已经完成物理真机验收。
