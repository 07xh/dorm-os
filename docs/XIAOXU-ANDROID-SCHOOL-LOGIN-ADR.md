# ADR｜校序 Android 使用学校真实账号，不再强制设置校序口令

- 状态：**已确认产品方向，技术落地待验证**（2026-11-04）
- 影响范围：`apps/xiaoxu-android`，现有 `/api/v1/*` 私人数据鉴权，学校连接器
- 原则：**增量复用，不重建 App，不把学校密码误当云端授权凭据**
- 参考体验：北化课表的“先选学校／登录学校教务／保持本机授权”；只参考交互，不复刻未知许可证的代码与图片。

## 0. 当前代码事实（main 审查口径）
1. Android 已有 Kotlin/Jetpack Compose + Room 的原生壳：`apps/xiaoxu-android/app/src/main/java/io/github/x07xh/xiaoxu/MainActivity.kt`，不是把网站当成唯一主界面。
2. `data/CloudClient.kt` 用独立的校序 `POST /api/v1/auth/login` 获得 `__Host-xiaoxu_session`，在 Android Keystore AES-GCM 加密存储；`ui/CloudPanels.kt` 目前仍有“校序个人口令（不是学校密码）”输入。它是**旧版云端鉴权**，不是青果、学习通或二课登录。
3. `lib/academic-access.mjs` 的私人 API 目前只认可 `owner_password` 或已配置的 Cloudflare Access JWT；`lib/academic-owner-session.mjs` 从 D1 查找未撤销、未过期的会话。删除前台密码输入不等于改造服务端；直接放行将泄露私人任务、微信候选和学业记录。
4. `lib/academic-school-login.mjs` 为学校连接保留严格的本人身份、可信适配器、加密会话保险库门禁。官网浏览器能登录 **不表示** 原生 App 或 Cloudflare 可以获得学校会话。真实华水本人首次登录及重启后刷新仍必须逐项验收。

## 1. 已确认用户体验
- 每次打开 App **直接进入原生首页**；Room 本机功能无需密码，可离线使用。
- 首次使用可在“我的 → 学校账号”选择 **学习通 / 青果教务 / 第二课堂**，不单独注册“校序账号”，不要求再设置一个新的校序密码。
- 各平台使用其**真实官方认证方式**；允许官方扫码、官网认证以及已核验的本机账号密码表单。**不得把青果密码用于学习通独立账号**。
- 成功连接后显示来源、学校验证状态、最近成功同步时间；会话有效时自动刷新。若无可用官方授权回调或可信适配器，只显示“未连接／需在官网操作”，**不能显示“连接成功”**。
- 云端功能是**可选**的；在未完成安全设备绑定前，本机任务与公开公告正常可用，私人云端数据保持未授权。
- 登出、撤销设备、过期、学校密码更改仅影响相应会话；不能自动登出其他平台。应用不持久化明文学校密码。

## 2. 两层不同的身份，不能混用
| 层 | 作用 | 新目标 | 不能做的事 |
| --- | --- | --- | --- |
| 校序 API 设备身份 | 控制 D1 私有任务、微信候选、已核验学业快照 | 设备绑定、短期可撤销授权，不靠每次输入校序口令 | 只凭安装 App、学号、可访问学校官网、请求头或前端声明放行 |
| 学校数据源授权 | 读取本人的青果/学习通/第二课堂记录 | 各自官方登录后严格验证身份并保留合规会话 | 将浏览器 Cookie 当作 App 已取得会话；绕过验证码/CAS；将单一平台会话通用于其他平台 |

学校真实密码**不能**直接替换 `OWNER_LOGIN_SECRET`：学校不替校序签发可信身份，Cloudflare 目前也没有可验证的学校授权回调。二者直接等同是安全回归。

## 3. 最小改造路线（先保留兼容，再安全迁移）
### P0｜设备授权契约与可信发起方
- 保留现有 Web / `owner_password` 私人接口，不改为匿名。
- 为 Android 设计**本机设备密钥**：优先 Android Keystore 非导出私钥，服务端只持有公钥、账号绑定、scope、状态及撤销时间；挑战随机数短效且一次性消费，签名验证和重放保护必须有服务端测试。
- 初次设备绑定必须由**已经被服务端独立验证的本人会话**显式批准。暂可复用原有 owner Web 会话完成**一次性迁移**，但不能要求用户长期维持“两个登录密码”。待学校身份在服务端可验证后，可评估替换这一步；**未验证时不开放自助匿名绑定**。
- 绑定必须防止他人手机用已知学号冒领，保护 XSS/CSRF、错误来源、重复挑战、时钟漂移、丢失/换机撤销。
- 私人 API 只在通过严格设备身份或现有验证的 owner/Access 时接入；记录迁移到同一 owner ID，**不建第二份学业/任务数据库**。
### P1｜真实平台连接（先学习通，再青果，最后第二课堂）
- **学习通**：复用仓库现有上游会话、作业解析、只读适配器；先验证官方首次登录→本人课程/作业→关 App 再启动后刷新。已有扫码/浏览器会话不能自动跨进程导入。
- **青果**：复用已有安全登录探测和课表解析；若官方纯密码表单已确认，提供原生账号密码输入且只把短暂凭据送往经验证的受信任路径；若需交互式 CAS，则转官方认证，不伪造自动登录。必须通过学号、学期与课表证据一致性门禁。
- **第二课堂**：优先官方学校 CAS，沿用当前禁用旧密码代理的边界；若没有受认可的会话关联机制，不制造“扫码成功即已连接”的假象。
### P2｜App 视觉迁移
- 用**原生**“选择学校／账号连接”底部抽屉或页面替换**用户可见的**校序独立口令入口；只有 P0 API 和首次注册流程实测后才能移除旧表单。
- 登录只在首次授权或某个来源会话过期时出现，平时展示动态原生课表与任务；登录不能成为启动页。
- 暂存未完成 App/网站会话迁移兼容代码至新方案通过回归，之后移除旧的校序口令入口和弃用逻辑；**先验证、后删除**。
- 不以静态假课程、模拟“已连接”状态、WebView/TWA 入口替代动态原生页面。

## 4. 端到端验收门禁
1. **安全**：无授权、伪造学号、无效签名、重复挑战、已撤销设备、过期授权和异设备持有旧凭据必须拒绝 `/api/v1/assignments`、`/api/v1/connections`、`/api/v1/wechat/candidates`；旧 Web 会话不回归。
2. **真实**：学习通真实课程和作业与本人官方页面逐条比对；再验收青果真实课表；最后二课活动、积分；必须包含首次登录、退出重新进入、会话续期/失效。
3. **体验**：手机/平板直接进首页，未登录仍能操作 Room 任务和浏览公开通知；已授权用户不再看到额外“校序密码”，仅单个失效平台提示重新连接。
4. **数据**：所有云端记录携带真实来源和已验证状态；旧 Room/D1/PWA 数据不被重置或冒充已同步。
5. **构建**：Android `assembleDebug`、Node/Playwright、设备身份与学校连接合成负例、Android 16 真机测；发布部署与线上 API 回归分别签收。

## 5. 不能提前宣称完成
此 ADR **只确定方向并记录现有安全边界**。没有实现新设备身份服务、学校官方身份回调或真实首次登录。直至 P0 验收，网站和原生 App 保持原有受保护的 `owner_password` 路径，不把私有云端 API 对匿名客户端开放。
