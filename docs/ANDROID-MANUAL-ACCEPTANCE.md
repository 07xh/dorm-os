# DORM OS Android / NFC 真机验收（待实际测试）

> 桌面/移动 Chromium 自动 E2E ≠ Android 硬件 NFC 验收；所有未实机确认的项目保持未完成。

## 设备与环境

- Android 16 一加手机，NFC 开启；使用支持 Web NFC 的浏览器、HTTPS 生产网址
- 至少一枚有权限写入的 NDEF NFC 标签；确认标签不是银行卡、门禁卡或其他禁止改写的凭证
- 备份现有 DORM OS 数据，测试专用标签不含任何账号密码或密钥

## 用例（必须记录手机系统版本、浏览器版本、标签类型、时间、结果）

- [ ] 从正式站点安装 PWA 到桌面，重新打开页面内容正确
- [ ] 离线打开已访问的 PWA，个人任务和场景仍能使用，天气状态正确标记不可更新
- [ ] NFC 页面报告 HTTPS 安全、Web NFC 支持状态；点「开始扫描」并在前台授权
- [ ] 将 DORM OS 学习 URL 写入测试 NDEF 标签，写入后用手机前台真实读取；标签提示“实机读取”而非只显示“写入”
- [ ] 将标签关联场景改成“开发”但不重写标签，旧标签触碰应被拒绝自动切换并提示重写
- [ ] 重写标签后，手机再次读取能够打开开发场景；执行状态不得写为“Android 系统已自动化”
- [ ] 如采用 MacroDroid 原生 NFC 标签：使用**另一枚标签**，在 MacroDroid 中配置 NFC 专用标识与系统动作；碰触后在 MacroDroid 内核对动作执行日志
- [ ] 在一加平板上通过密码加密 JSON 恢复个人备份，确认任务、课程、标签与场景快捷入口；错误密码不能恢复
- [ ] Android 返回键、浏览器刷新、后台恢复、旋转屏幕没有损坏个人数据

## 记录结果

填写：设备型号 / Android 版本 / 浏览器名称与版本 / NFC 标签型号 / 页面地址 / 触发前与触发后状态 / MacroDroid 日志（如适用）/ 通过或失败。

网页 JavaScript 无法凭空判断另一 App 是否改变了系统设置；没有可验证回执时，界面只报告「已打开网页」或「已切换本站场景」。

## 写入取消与实机状态

- [ ] 写入 NFC 等待期间点击「取消写入」，页面取消请求且不会错误标记写入成功
- [ ] 在等待写入时切换到「场景」页，操作应终止且不会保存 `writtenAt`
- [ ] 写入成功后状态只显示「待重新扫描验证」；再次真正读取同一标签后才显示已验证
- [ ] 切换场景绑定后旧读取证明作废；改绑为开发场景后先重写再读取以确认

注意：CI 的 NFC 模拟器只模拟浏览器 API，不能证明手机或标签物理行为。
