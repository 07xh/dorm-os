# 校序任务中心 UI 与交互重构设计 · B 执行优先

日期：2026-11-13（北京时间）
状态：设计评审稿；用户已选择 B 并接受父任务手动确认结束规则。其余提案需整体设计确认后进入实施计划。尚未修改产品代码、合并 PR 或发布 APK。
建议归档位置：docs/superpowers/specs/2026-11-13-task-center-design.md。

## 1. 意图与成功标准

用户打开任务中心即可知道现在能做什么；复杂任务可以拆成步骤，完成前置后下一步自然出现；任务完成操作及时、可信、可撤销。手机日常使用优先，延续现有 Kotlin/Compose、共享设计系统与液态玻璃导航。

成功标准：用户无需进入任务管理页即可新建、完成、查看步骤及编辑个人日期；不必读说明文字判断任务是否能做；官方状态与个人执行进度不会混淆；切页、保存及刷新不丢失定位和数据。

不纳入本轮：重建导航、学校连接器、数据库系统、消息审核系统；自动提交学校作业；新增 AI 自动拆解、提醒服务、云端父子任务同步。独立平板布局重构应在同一数据与动作契约上另行设计，不能另造任务系统。

## 2. 已选方案与备选

| 方案 | 优点 | 代价 | 决定 |
|---|---|---|---|
| A 清单优先 | 操作熟悉、组织简单 | 用户仍需自己判断下一步 | 未选 |
| B 执行优先 | 可执行步骤直接可达、依赖自动解锁 | 需定义步骤归属、依赖、完成规则 | 用户已选 |
| C 项目优先 | 阶段和复杂项目组织完整 | 层级和维护成本较高 | 未选 |

父任务结束规则：用户接受子步骤全部完成后显示“步骤已完成，待确认结束”，父任务需要最后一次个人确认。任何个人操作都不能改写学习通官方状态。

开放 PR #429 包含现在可做、等待前置、Room v4 依赖关系、备份扩展、关系图以及新建/管理分离等工作；不等于已合入或当前安装包已有。#415 涉及统一个人编辑及微信计划日期。实施前必须重新读取 main 与这两项最新精确 HEAD，核对实际差异和消费者，选择唯一修改线，禁止旧分支整文件覆盖。

复用 RealAcademicTaskHub、TaskBoard、LocalTaskDatabase、CloudClient、现有 WorkspaceTask 来源身份、XiaoxuDesignSystem、统一弹层、归档与备份路径。前置关系与父子归属是不同概念；不能用已有 DAG 假称已实现任务分解。

## 4. 页面信息结构

顶栏：任务标题、搜索、新建、更多。主视图顺序：现在可做、待完成、全部、已完成。首次默认现在可做，普通切页恢复视图与滚动位置。

来源与日期是独立筛选条件，不占用状态视图；启用后明确显示条件，并可一键清除。搜索按标题及现有可搜索字段过滤；子步骤命中时保留父任务上下文。状态计数以未应用搜索/来源/日期的根任务数量计算，显示计数与“可做步骤数”不同语义，不混用。

“待完成/全部/已完成”按来源分组，首次全部折叠，之后保留用户选择。微信已审核任务独立分组；候选仍在消息中心，不计入正式任务。

“现在可做”按逾期、今天、接下来、未设日期分区，空区隐藏；同一分区按最早有效日期排序，无日期按创建时间稳定排序，稳定 ID 作为最终排序键。“接下来”表示未来有日期的可做事项，不推断任何新截止日期。

等待前置、学习通待核对置于独立折叠区；刷新不会自动展开。“没有可做事项”与“没有任何任务”“筛选无结果”“读取失败”分别展示对应状态和恢复动作。

日期沿用现有个人计划日期与可信官方日期策略，按 Asia/Shanghai 解释学校日期；缺失年份或未核验旧快照不得推算为今天。步骤有个人日期时使用自己的日期，否则以父任务已有有效日期作为参考，标明继承语义，不写回步骤日期字段。详情保留个人计划与来源原截止。

## 5. 任务与子步骤模型

设计提案：首版只支持一层子步骤，避免无限嵌套增加手机操作负担。每个子步骤恰好属于一个根任务，不可成为另一个步骤的父级。普通任务不必创建步骤。

根任务可以是本机个人任务、已审核微信任务或具有稳定官方身份的学习通作业。子步骤属于个人执行记录，本轮保存在既有本机 Room 中，不宣称跨设备同步。云端普通个人任务附加步骤亦按同一稳定来源键处理。

根任务引用必须使用来源、账户范围和稳定记录 ID，绝不按标题绑定。本人账户切换时隔离相应来源的步骤；未登录不展示其他账户步骤。纯本机任务维持现有归属策略。无可靠身份的历史通知不可附加步骤，先进入待核对。

依赖默认不存在，步骤可任意顺序完成；高级设置可指定同一个父任务下的多个前置步骤。首版不支持跨父任务的“子步骤依赖”。#429 已有独立本机任务间依赖应保留，其既有数据与能力不删；父任务自身被该依赖阻塞时，其所有未完成步骤也等待。

任何依赖写入拒绝自环、间接循环、悬空引用和越权引用；完成操作在既有数据库事务内复核前置。具体新增表、列、索引和版本号由实施者按最新基线决定，不创建第二个数据库。

## 6. 可做列表、进度与计数

没有步骤：根任务若可信待办且前置满足，展示根任务本身。

有步骤：展示当前可执行的未完成步骤，副行展示父任务标题与完成数 x/y；父任务不同时成为重复可勾选行。若多步可并行，可展示多行，并明确各自所属任务；来源信息可通过紧凑标识及读屏获取，详情完整保留。

步骤全完成、根任务未结束：现在可做中出现一条“确认结束”操作，附父任务标题。根任务完成之前仍计入待完成。根任务计数始终按唯一根 ID 去重，步骤数单独计算，不因拆成五步就让总任务数增加五条。

学习通官方已完成记录退出可做列表，未完成个人步骤保留在详情，提示官方状态变化，不丢弃个人记录。未知或过期状态不因个人步骤就变成可信可做事项；用户可以在详情继续管理个人记录，但官方待核对分类保留。

学习通个人步骤已确认结束、官方仍可信未提交时，保留一条“前往学习通核对并提交”的根任务动作，不再列出已结束步骤；它仍按官方待办参与待完成根任务计数。点击只打开现有学校入口，绝不自动提交；官方可信完成后才转入官方已完成。个人步骤结束不能把官方待办隐藏。

## 7. 完成与撤销规则

本机/微信根任务有未完成步骤时，不提供“一键全部完成”；点击根完成入口定位到剩余步骤。步骤全完成后，用户确认个人结束；学习通仅保存“个人步骤已结束”，官方状态保持原值。

本机根任务已结束后再新增或重新打开步骤，同一 Room 事务清除个人结束标记，使任务重新进入待完成；学习通的本机个人步骤结束标记也按此处理，官方已提交状态不受影响。界面明确反馈“个人任务已重新打开”。

微信等远端已结束根任务采用显式两阶段交互：先通过现有 CloudClient 在线重新打开，服务器确认后才允许新增/重开本机步骤。离线或冲突时保留原步骤并提示先重开父任务，不创建隐式待同步动作。若远端重开成功而随后本机步骤写入失败，远端根维持已重开，界面说明“父任务已重新打开，步骤保存失败”并允许重试；不承诺跨服务器与 Room 的原子事务。远端仍待完成的根任务可离线管理本机步骤，结束远端根仍需在线确认。

撤销前置步骤时，已经完成的后续步骤保留历史完成状态，不级联抹除；尚未完成的后续步骤重新等待。若根任务已结束，则依照上条重新打开。已有根任务依赖撤销采用同样保留历史原则，并复用现有契约。

点击完成框立即出现当前行反馈，保存中限制当前行重复提交，其他任务可操作；权威进度与依赖解锁在事务/服务器确认后更新，不提前解锁。成功后短暂保留反馈再移出当前视图，提供可撤销入口；失败恢复原状态，保留滚动位置并提示重试。远端写成功但回读失败不得显示“未保存”，应提示已保存、状态待刷新。

撤销也必须是一次真实写入，若版本冲突则刷新并提示，不能只改画面。官方只读状态使用状态图标而非可点复选框。

## 8. 详情、新建与编辑

点正文打开唯一详情；点完成框只处理完成；父任务名称可进入父详情；等待原因可定位具体前置。避免重叠点击区域。

详情顺序：标题与日期、个人进度/下一步、子步骤、来源原始内容及链接、官方状态与读取时间、更多操作。一般用户不必阅读身份 ID、开发说明或核验原理。

新建普通任务只需标题；日期、步骤可后补。添加步骤支持连续输入与键盘下一项；前置设置默认折叠。新建/编辑采用既有统一编辑器体系中的对应模式，保存失败保留输入；不将任务管理、筛选列表和新建表单堆在同一个弹层。

步骤可编辑标题、个人日期、调整顺序和删除。调整顺序只改变展示顺序，绝不偷偷重写依赖。首版使用明确的上移/下移入口，拖拽留作后续验证，不作为必需手势。

删除含步骤的本机根任务先确认，并明确相关个人步骤与依赖的影响；有依赖的步骤删除前说明后续将解除该条件。事务删除，不留下悬空边。官方记录不能通过个人删除动作从学校删除；继续沿用已有归档/隐藏语义。读取失败或官方列表暂时缺席不级联清理个人步骤；可信官方删除记录保留历史及个人记录，退出可做列表。

## 9. 存储、离线与备份

步骤、依赖、个人结束状态纳入既有 Room 非破坏性迁移、备份与恢复；导出在同一事务读取完整快照。旧备份继续可读，新备份保留父子归属与依赖，导入须重新映射本机 ID 并完整校验；失败整笔回滚。外部来源稳定键与账户范围一并保留，只有当前账户匹配时才关联展示，不能跨账户匹配。

本机个人操作离线可保存；远端根任务个人完成/日期操作沿用当前 CloudClient 可用性与版本契约，不新增隐式离线队列。远端操作不可用时明确禁用对应动作，本机步骤管理仍可保存；“结束微信父任务”必须等远端确认，不能因本机步骤结束伪称云端完成。

进程退出后以持久状态重新计算可做/等待，不能靠内存乐观态恢复。授权失效保留历史读取结果，提示重连对应来源；不将失败当作空数据。

## 10. 视觉、性能与可访问性

沿用共享字体、背景、间距、玻璃弹层和导航，不增加独立视觉系统。正文以标题、日期、执行入口为主，不堆多层卡片与解释小字。

完成框、更多按钮等交互目标保持至少 48dp；长标题允许两行，读屏提供完整标题、所属任务、步骤进度及保存状态。颜色之外必须有文本或图标区别逾期、等待和完成。

列表使用稳定键及真正惰性行，不能在一个 LazyColumn item 中一次性展开数百个子组件。行级写入避免重算整个列表、回顶及大面积布局跳动；键盘弹出后输入和保存按钮保持可达。动效时长由现有设计系统决定，尊重系统减少动画设置。

## 11. 验收场景

| 场景 | 必须得到的结果 |
|---|---|
| 普通任务无步骤 | 创建、完成、撤销及日期编辑保持可用 |
| 四步顺序任务 | 一步保存成功后解锁下一步；父任务不重复显示 |
| 多前置/并行步骤 | 只有全部前置完成才解锁；并行步骤可分别操作 |
| 步骤全部完成 | 显示确认结束；确认之前父任务仍待完成 |
| 重开步骤/新增步骤 | 个人父任务重新打开，官方状态不变 |
| 撤销前置 | 未完成后续重新等待；已完成后续历史保留 |
| 来源与官方状态 | 微信候选不入列表；学习通未知进待核对；已提交不伪装未提交 |
| 搜索与筛选 | 命中步骤保留父上下文；清除条件可恢复完整结果 |
| 保存失败/冲突 | 无假成功、无重复提交、无滚动丢失；可恢复操作 |
| 断网/重启/切账户 | 本机进度持久；远端动作诚实；账户数据隔离 |
| 旧库/旧备份 | 原地迁移不丢旧记录；关系映射正确；异常导入回滚 |
| 长列表与连续操作 | 200 根任务及多步骤下连续勾选、展开和切页无明显卡顿 |

自动化覆盖状态推导、依赖事务、来源身份、迁移及备份兼容；交互测试覆盖新建、步骤编辑、保存失败和筛选。Ace 6 Android 16 以真实存量任务核对，记录完成反馈延迟、滚动及切页帧数据，禁止仅凭编译成功宣称验收。

## 12. 实施者可自行决定与后续边界

实施者自行决定：在既有架构内如何拆分 Composable/状态推导函数、具体 schema 版本与索引、测试文件归属、共享组件复用、短反馈持续时间。必须以最新 main/开放分支差异为依据。

本轮父子步骤仅本机持久化；未来云端同步、跨父任务步骤依赖、更多层级、拖拽排序及 AI 拆解需要单独设计。不得把这些后续能力描述为当前已实现。

正式实施前整体确认本设计；之后生成按模块的实施计划。发布时分别报告源码、CI、APK、迁移、本人真实来源数据及真机交互结果。
