# 第二课堂既有会话续接修复

**目标：** 修复本机第二课堂把正常学校登录跳转、临时 403 误判为必须重新授权的问题。

**范围：** 复用现有 WebView Cookie、本人身份哈希、Room 原子快照和已开启的后台任务；不导出 Cookie、不提交登录表单，不改变学校会话真实期限。

## 实施和验证

- [x] 先用现有设备隔离运行测试复现：403 不应永久停读；学校已知 GET 登录中转应可返回积分页；外站跳转继续阻止。Android 16 运行 42365225364 已复现 4 处预期失败。
- [x] 在现有自动读取策略增加严格学校导航白名单：HTTPS 默认端口、固定积分页/中转路径、CAS 固定 service、有限跳转次数。
- [x] 自动 WebView 只允许正常 GET 续接；停留在真实登录页时停止并要求本人操作，不执行凭据填写或表单提交。
- [x] 积分页 401 保留重新连接；下游活动 401、403/网络/外站拦截保留历史数据并作为可恢复失败；只有核验账号不同才要求本人确认。
- [x] Kotlin/JVM、完整仓库 CI 与 26 项 Android 16 隔离 WebView/后台运行测试通过；#386 已合并到既有 #351（518c054f），另含活动目录持久化与真实空筛选修复。

## 核验重点

- 官方 CAS 与中转完成后重新核验当前可见本人账号，不能只凭跳转判定成功。
- 真实登录页停留、学校跳转循环、异站/非默认端口/错误 CAS service 均不能写入数据。
- 关闭自动或后台开关、手动读取、取消和进程退出保留现有互斥与清理。
- 403 后下一次合法调度应可再次读取；不增加高频重试、强制后台或唤醒锁。
- APK 编译和隔离测试不能替代本人学校账号在 Ace 6 上的重启与持续续读验收。
