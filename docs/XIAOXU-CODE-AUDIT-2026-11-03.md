## 3. 核心逻辑审查结论

1. **只有一套前台数据连接中心**：`我的 → 数据连接`；私有 `/api/v1/connections` 读取三个来源状态。每个平台受 `academicSchoolAdapters` 的可信服务端注册限制；前端 JSON 无法注入适配器。
2. **认证互相独立**：校序单用户 Owner 或 Access 身份；青果 CAS、学习通独立账号、第二课堂 CAS 分别维护上游会话；不把另一个标签页中已登录官网的 Cookie 当作已绑定校序。
3. **学校账号持久化机制已有代码**：`academic_provider_sessions`、AES-GCM、用户和来源绑定；`review_pending` 的青果课表不会直接当可信同步数据。密钥错误或过期时不得显示活动授权。
4. **学习通 CLI 导入和站内实时连接不是同一回事**：`xuexitong-cli` 合同导入是用户导入；站内连接依赖 `createChaoxingSchoolAdapter`、密钥、D1 与本人身份验证，不能伪称二者等价。
5. **前台刷新≠后台任务**：目前前台 15/30 分钟按需检查不支持关闭页面后的系统推送；不要在 UI、README 或进度表中称作已实现的后台同步。
6. **兼容资产不能粗暴删除**：旧 DORM OS 本地备份格式、NFC 链接、`/login/`、旧迁移表、分层 CSS、个人任务和导入入口仍有使用路径。本轮未删数据库迁移或清除任何生产记录。

## 4. 尚未解决的 P0 / P1（必须单独验收）

- **P0 青果**：实际学校 CAS 登录链路、可能的二次教务账号、本人学号绑定、真实课表星期/节次/周次/教室逐项比对，完成后重新进入网站刷新；成绩、考试仍不能冒充已接入。
- **P0 学习通**：生产侧公开上游可达性曾失败；区分超星独立账号与华水校园 CAS，验证本人的课程、收件箱、作业与截止日期；只凭 CLI 或本地测试不能签收。
- **P0 第二课堂**：必须以学校当前普通登录方式验证首次真实登录、活动/积分读取、加密会话重开续用；遇验证码或交互式挑战时安全停止而非绕过。
- **P1 UI 与前端维护**：`public/index.html` 仍是大文件，当前共 6 个被引用的 CSS 层。后续按实测页面、计算样式、Playwright 回归逐层合并，不能把所有 V8/V9 CSS 当成死代码。
- **P1 状态与提醒**：区分「服务端已配置」「官网连通」「真实登录成功」「数据已验证」「后台自动更新」。后台 Cron 与手机系统通知仍未完成且不得伪报。
