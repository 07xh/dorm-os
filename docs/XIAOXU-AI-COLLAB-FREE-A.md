# 校序 · Academic OS｜免费 AI 协作规则（方案 A）

> 本文档仅定义跨 AI 协作，不表示 AI 已与第三方产品相互联网或已获得代码推送权限。当前仓库：`07xh/dorm-os`；Android 工程：`apps/xiaoxu-android/`。

## 唯一代码来源与任务队列

- GitHub `main` 与对应的 Issue / PR / CI 是唯一可核验事实来源，不以任何 AI 对话中的“已经完成”为依据。
- 一项需求只指定一位实现负责人，使用 GitHub Issue 明确范围、排除项、修改文件和验收方式。
- 开始前必须查重开放 Issue、PR、分支和最近合并记录；如已有工作，优先续接/审查，不重建。
- 无人可直接推送 `main`。修改仅在独立分支提交 PR；需要测试、人工复核后再合并。
- 不把一份回答里的代码直接粘贴覆盖未读取的完整文件。须先取得当前源码，再生成定位清晰的统一 diff 或逐文件完整变更。
- AI 不能自动共享上下文；每次交接至少给出仓库、Issue/PR、基准提交 SHA、相关文件、测试结果、尚未验收事项。

## 职责和互斥编辑范围

| 角色 | 负责 | 禁止 |
|---|---|---|
| ChatGPT / GitHub 工作流（唯一整合者） | 安排 Issues、核对已存 PR、修复学校真实数据接入、服务端接口、身份安全、CI、合并与发布核验 | 不与 DeepSeek 同时修改同一 UI 文件，不将构建成功等同本人账号验收 |
| DeepSeek 免费网页版（UI 子任务实现） | 依据当前真实 Kotlin 源码，仅设计/生成 `apps/xiaoxu-android/` 中经过任务指派的 Jetpack Compose 视觉与交互文件及对应 UI 测试 | 不改 `functions/`、`lib/`、`integrations/`、云端认证、数据库、学校适配器、权限、`main`；不自行创建第二个 App 或第二套数据模型 |
| Claude 免费版（独立审核者） | 审查给定 PR 的差异、重复逻辑、Compose 可访问性、状态一致性、性能及潜在回归；给出文件/行号、证据、优先级和最小补丁建议 | 默认不负责实现，不直接推送、合并或扩展任务范围 |

如 DeepSeek / Claude 网页版不能直接读取仓库，使用明确选择的源码文件或无敏感信息的 diff 手动传递，不假定其已连接 GitHub。

## 首个 DeepSeek 任务建议（不与核心数据接入竞争）

> 只在任务分配后执行；先获得当前 Kotlin UI 原文件，不能按想象新建目录或包名。

**Android 课表页的「未连接 / 加载 / 错误 / 已验证」四态 UI 与交互细节**。

- 仅修改分配的 Compose 屏幕/组件和 UI 测试；不创建新登录入口、网络调用、Room 表或模拟课程。
- 状态来自现有 App 的真实数据接口；如果尚无可信课表，必须显示「未连接」或对应真实状态，不构造课表。
- 参考北化课表的交互密度和信息层次，但不复制 APK 反编译资源、专有布局或代码。
- 必须考虑窄屏手机、平板、深浅色主题、触控尺寸及可访问性。
- 交付：已用源码文件清单、修改 diff、关键状态说明、必要测试、编译能否实际验证（未运行要明确说未运行）。

## 审核和合并门禁

1. ChatGPT 在 GitHub 创建任务 Issue，确认无重复的活动 PR。
2. DeepSeek 仅用用户提供的当前文件和任务卡生成 UI 补丁；不要求收费 API 或 GitHub token。
3. 用户把补丁或 diff 交给 ChatGPT；由 ChatGPT 对照仓库最新代码做冲突处理，并提交独立分支 PR。
4. Claude 对该 PR 的 diff 进行独立审查；用户把审查结果交回 ChatGPT。
5. ChatGPT 运行/检查 `gradle -p apps/xiaoxu-android :app:assembleDebug --no-daemon`、相关 UI / JVM 测试、受影响的仓库检查；未真实运行的测试必须明确。
6. CI 通过且审查问题关闭才考虑合并；发布还需 Android 16 真机与本人真实来源核对，不允许因合并就声称平台接入成功。

## 数据安全

任何平台不得接收个人学校密码、原始 Cookie、微信 Token、Cloudflare Secrets、CAS ticket、未脱敏 HAR 或私人课程/作业记录。只提供脱敏日志、结构说明、公开代码或合成测试数据；不得绕过官方验证码、MFA 或访问控制。
