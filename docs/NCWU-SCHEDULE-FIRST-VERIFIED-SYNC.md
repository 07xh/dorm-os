# 华水青果：先课表、后成绩与考试的可信同步阶段

## 已有障碍

原有 `runVerifiedNcwuSync` 强制同一轮同时查询、验证三个 `schedule / grades / exams` 领域。即使本人课表已正常授权读取，如果成绩或考试接口尚未接入，也会整轮失败，无法先完成第一张真实课表验收。

## 这次修改

保留默认行为（三类全部收集），但仅允许**可信服务端调用者**指定 `kinds:['schedule']` 进行课表先行的同步：

- 学校会话必须已存在，且 `verifySession()` 需独立证明学校域名、本人身份、校序 owner 绑定、访问范围。
- `readSection('schedule')` 必须证明数据完整；空课表需独立 `verifiedEmpty:true`，不能把网络失败当无课。
- 记录必须包含稳定且经核验的来源 ID 和学期，**未验证 HTML 候选不能写入**。
- 存储只更新 `schedule` 快照，不读取、伪造、覆盖 `grades` / `exams` 快照。
- 学校连接总体状态标记为 `partial`，只有一次真实且完整的三类同步才变为 `connected`。
- `kinds` 为校序内部服务端参数，绝不允许客户端通过查询参数或 JSON 声称“已验证”。
- 课程存在未解析时间片段时仍不可进入本可信同步阶段。

## 合成验收

扩展已有 `scripts/xiaoxu-ncwu-verified-sync-tests.mjs`：

1. 只提供合成课表的受信任适配器，故意让成绩查询不可用，课表单独通过。
2. D1 只出现课表 batch，连接总体状态必须是 `partial`。
3. 后续再以三类完整合成数据升级为 `connected`。
4. 非本人会话、非法 `kinds`、重复分类全部拒绝，数据库与账号隔离仍然有效。

## 不代表真实学校授权已完成

这项改动只是解除“必须同时接齐成绩和考试”的内部依赖，不提供学校密码收集、模拟平台认证或凭 HAR Cookie 伪造连接。

下一验收仍是：使用学校许可的本人会话，证明课表完整、归属本人、每条课程来源 ID、周次节次与原官网完全一致。合成测试不能代替真人授权。
