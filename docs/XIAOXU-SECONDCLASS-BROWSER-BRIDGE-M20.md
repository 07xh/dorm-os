# 校序 M20｜第二课堂本人浏览器同步桥接

## 为什么本阶段不是“校方 OAuth 授权”

华水第二课堂官方网站使用校方 CAS 登录并回跳到校方站点，而不是校序
域名。校序无需学校开放 OAuth 才能管理**用户本人导入**的数据。
但未取得学校对校序的可验证授权时，不能把用户浏览器中的登录状态
伪称为校序云端取得的独立学校登录授权。

本实现是第三种方式：**用户正常登录学校官网 + 本人浏览器运行
ScriptCat 只读脚本 + 用户主动提供校序单用途配对密钥**。
脚本只访问既有 HAR 已确认的本人只读活动与分数接口，不劫持
CAS 流程，不读取学校密码、Cookie 或验证码，不代替用户登录。

## 已开发的数据流

1. 用户在校序「我的 → 数据连接 → 第二课堂」点击生成配对密钥。
   `POST /api/v1/second-class/bridge` 需要校序本人有效会话及同源防护。
   密钥仅在创建响应中显示一次，D1 只存 SHA-256 摘要；
   有效期 30 日，可以立即重置与撤销。
2. 用户在本人设备的 ScriptCat 安装已存在的
   `public/xiaoxu-second-class-export.user.js` v0.2.0。
   脚本现在额外具备「首次连接 / 立即同步 / 断开本机配对」功能，
   使用 `GM.getValue/GM.setValue` 保存在脚本私有存储中。
3. 当本人正常打开已登录的 `dekt.ncwu.edu.cn` 页面时，
   脚本使用**已有同源只读 POST**得到活动分页，检查身份一致、
   分页完整、已核算积分及素质分结构，并只将
   `xiaoxu/academic-snapshot-v1` 活动字段脱敏。
4. 脚本通过固定的 `GM.xmlHttpRequest` @connect 校序地址提交
   `Authorization: Bearer <pairing-token>`，设置
   `anonymous:true` 不携带校序 Cookie；Cloudflare 私有桥
   `POST /api/v1/second-class/bridge/ingest` 仅接受第二课堂
   用户快照，校验 SHA-256 摘要、时间、归属与来源后使用原始
   D1 个人快照写入器原子保存。
5. `GET /api/v1/connections` 会在第二课堂卡片显示配对状态和
   最近同步时间；`DELETE /api/v1/second-class/bridge` 撤销授权。
   旧个人学业记录保留，不影响青果、学习通和校序本人登录。

## 限制与防护

- 每十分钟最多接受一批，脚本页面加载时尝试一次，此后约 30 分钟
  以及页面重新变为可见时检查。学校网页关闭、Android 限制后台运行、
  学校会话到期、网络不可用时，都无法保证继续更新。
- **这是浏览器主动同步，不是 Cloudflare 完全无人值守的服务端同步。**
  自动同步成功的记录仍是 `user_import`；没有假装经过
  独立学校认证的 `trusted_readonly`。
- 脚本后台上传只包含严格白名单的活动快照；
  学校页面素质分与志愿服务总计依旧仅做本机核对预览，
  不会冒充后端的校方官方总计。
- 无效、过期、撤销、轮换的密钥不可使用；配对仅授权写入本人
  第二课堂快照，不允许读取云端账号、课程、成绩或密码。
- 任何已存在可信学校同步批次均不能被此个人导入覆盖。
- 校序不收集学校账号密码、微信 token、CAS ticket，也不会跨站读取
  学校 Cookie。
- 脚本访问地址被固定在 `dorm-os-dk9.pages.dev`，如将来切换
  校序正式域名，需要显式审核并更改 @connect 配置。

## 验收

`node scripts/xiaoxu-secondclass-browser-bridge-tests.mjs`
覆盖本地 SQLite 真实 D1 数据模型：密钥摘要不可逆、配对重置、
撤销立即生效、非法来源、十分钟频率限制、本人数据隔离、
可信数据不可覆盖、原有 ScriptCat 导出逻辑不失效。
`npm run check` 和 Playwright 桌面/移动回归必须通过才合并。

生产须执行 0013 前向 D1 迁移。合并发布后，用户仍应在本人
已登录的真实第二课堂页面做一次真机测试，并与官网活动数量核对；
测试通过前**不宣称学校真实自动同步已验收**。
